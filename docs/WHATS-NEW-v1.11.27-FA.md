# راهنمای نسخهٔ ۱.۱۱.۲۷ — «دریافت خوراک ناموفق» دیگر خطای دروغین نیست

گزارش کاربر: «میگه دریافت خوراک ناموفق این مشکل ریشه ای درست کن»

## علت (ریشه پیدا شد و تأیید شد)

پیام «دریافت خوراک ناموفق» فقط در پنل مدیریت، بعد از زدن دکمه‌های
«بررسی خوراک کاربران» یا «بررسی خوراک بنرهای کاربران» دیده می‌شود.
بازرسی زندهٔ مخزن نشان داد هر دو فایل خوراک سالم‌اند:

- `feed/announcements.json` ← پاسخ ۲۰۰ و محتوای `[]`
- `feed/main_ads.json` ← پاسخ ۲۰۰ و محتوای `[]`

یعنی دریافت **موفق** بوده؛ خوراک فقط **خالی** است — که بعد از حذف همهٔ
اطلاعیه‌ها/بنرها و زدن دکمهٔ انتشار (رفتار درست از نسخهٔ ۱.۱۱.۲۶) حالت
کاملاً طبیعی است. اما کد پنل «تعداد صفر» را با «دریافت ناموفق» یکی می‌گرفت
و پیام خطا می‌داد؛ حتی متن خطای بعد از کولون خالی بود، چون خطایی در کار
نبود. سه اشکال ریشه‌ای در همین مسیر پیدا شد:

1. **خوراک خالی = خطا**: `checkFeed` فقط یک عدد برمی‌گرداند و پنل هر «۰»
   را «ناموفق» نمایش می‌داد — چه واقعاً شبکه قطع باشد چه خوراک خالی.
2. **تلمیح پاسخ غیرآرایه**: `FeedFetcher.fetch` هر پاسخ غیرخالی را «موفق»
   می‌شمرد؛ اگر شبکهٔ بین‌راهی (مثلاً پورتال اینترنت هتل یا صفحهٔ خطای
   HTML با کد ۲۰۰) متن غیر JSON می‌داد، همان «موفق» تلقی و حتی **کش محلی
   با HTML آلوده می‌شد** و تا دریافت موفق بعدی، خوراک خراب نمایش داده
   می‌شد.
3. **خطاهای بی‌معنی**: کدهای خطا فقط به‌شکل «کد ۴۰۴» نمایش داده می‌شد و
   مدیر نمی‌فهمد مشکل از کجاست.

## تغییرهای این نسخه

- **چهار حالت جدا به‌جای یک پیام**: دکمه‌های بررسی خوراک حالا دقیقاً
  وضعیت واقعی را می‌گویند:
  1. «خوراک فعلی کاربران: n اطلاعیه/بنر — دریافت موفق از …»
  2. «خوراک در حال حاضر خالی است — دریافت موفق از …» (مشکلی نیست؛
     یادآوری اینکه برای رسیدن آیتم تازه دکمهٔ انتشار را بزنید)
  3. «الان به منبع زنده دسترسی نبود — آخرین نسخهٔ کش‌شدهٔ دستگاه: n …»
     (نام منبع کش و جزئیات تلاش‌ها)
  4. «دریافت خوراک ناموفق: …» فقط وقتی واقعاً همهٔ منابع شکست خورده‌اند،
     همراه با راهنمای بررسی اینترنت و نام منابع آزموده‌شده.
- **اعتبارسنجی آرایهٔ JSON در خود FeedFetcher** (پارامتر `jsonArray`):
  پاسخ غیرآرایه از هر منبع رد می‌شود و منبع بعدی آزموده می‌شود؛ کش محلی
  دیگر با HTML آلوده نمی‌شود. این محافظت در هر چهار مسیر اعمال شد:
  `fetchFeed` و `sync` هر دو خوراک اطلاعیه و بنر.
- **شرح کدهای خطا**: ۴۰۴ ← «فایل در این منبع نیست»، ۴۰۳ ← «محدودیت یا
  مسدودسازی» — برای عیب‌یابی سریع‌تر در پنل.

## نتیجه برای مدیر

- بعد از حذف همهٔ اطلاعیه‌ها/بنرها و انتشار، «بررسی خوراک» می‌گوید
  «خوراک خالی است — دریافت موفق» نه «دریافت خوراک ناموفق».
- اگر واقعاً شبکه قطع باشد، پیام خطا نام منابع شکست‌خورده و علت هر کدام
  (۴۰۴/۴۰۳/کد دیگر) را نشان می‌دهد.
- رفتار همگام‌سازی کاربران تغییری نکرده — فقط دقیق‌تر و ایمن‌تر شده است.
