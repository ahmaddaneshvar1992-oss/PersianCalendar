# تقویم فارسی — راهنمای ساخت و اجرا

سورس کامل اپلیکیشن اندروید «تقویم فارسی» با Kotlin و Jetpack Compose.

## مشخصات

| مورد | مقدار |
|---|---|
| نام اپلیکیشن | تقویم فارسی |
| شناسه پکیج | `ir.persiancalendar.app` |
| نسخه | 1.0.0 (versionCode = 1) |
| زبان | Kotlin + Jetpack Compose (Material 3) |
| minSdk | 24 (اندروید ۷) |
| targetSdk / compileSdk | 35 (اندروید ۱۵) |
| فونت | وزیرمتن (مجوز آزاد SIL OFL 1.1) |
| تبلیغات | AdMob — بنر + اینترستیشال (فعلاً با شناسه تست) |

## امکانات (نسخه ۱.۲.۰)

- تقویم ماهانه و هفتگی شمسی + نمای روزانه
- تبدیل شمسی ↔ میلادی ↔ قمری
- مناسبت‌های رسمی ایران + تعطیلات (کاملاً آفلاین، فایل `assets/holidays.json` قابل ویرایش)
- افزودن رویداد با یادآوری و تکرار (روزانه/هفتگی/ماهانه/سالانه شمسی)
- ویجت صفحه اصلی
- اوقات شرعی (روش رسمی مؤسسه ژئوفیزیک دانشگاه تهران) برای ۳۹۶ شهر/شهرستان همه استان‌ها
- انتخاب استانی/شهرستانی جدا + جست‌وجوی سراسری + مکان‌یاب (نزدیک‌ترین شهر با GPS)
- اذان دلخواه: انتخاب صدای اذان (مشهد/حاج‌اصغر/نجف/بدون صدا) — فایل‌های قابل تعویض در `res/raw`
- پنل مدیریت تبلیغات با رمز: روشن/خاموش بنر و اینترستیشال، تناوب نمایش، شناسه واقعی AdMob، آمار و کاربران
- حساب کاربری محلی (ثبت‌نام/ورود) و عضویت ویژه حذف تبلیغات (Google Play Billing + کد فعال‌سازی)
- جهت قبله
- اعلان هوشمند اوقات شرعی و یادآوری رویدادها
- تم روشن/تاریک + ۴ پالت رنگ
- پشتیبان‌گیری محلی (خروجی/ورودی فایل JSON)
- راست‌به‌چپ کامل و ارقام فارسی

## ساخت پروژه

### پیش‌نیازها
- **Android Studio** (نسخه Ladybug 2024.2.1 یا جدیدتر)
- JDK 17 (همراه Android Studio موجود است)

### مراحل
1. پوشه `PersianCalendar` را باز کنید: **File → Open** و انتخاب پوشه‌ای که این فایل README در آن است.
2. منتظر بمانید تا Gradle Sync کامل شود (بار اول چند دقیقه طول می‌کشد چون Gradle 8.11.1 و کتابخانه‌ها دانلود می‌شوند؛ اینترنت لازم است).
3. برای اجرا: یک دستگاه/شبیه‌ساز وصل کنید و **Run ▶** بزنید.
4. برای خروجی انتشار: **Build → Generate Signed App Bundle / APK**.

> نکته: اگر Android Studio پیام «Gradle wrapper not found» داد، فایل `gradle/wrapper/gradle-wrapper.jar` و اسکریپت‌های `gradlew` به همراه پروژه هستند؛ در صورت مشکل از منوی **File → Sync Project with Gradle Files** استفاده کنید.

```
├── MainActivity.kt            ← اکتیویتی اصلی (Compose + RTL)
├── core/
│   ├── calendar/              ← تبدیل جلالی/میلادی/قمری + متن فارسی
│   ├── prayer/                ← اوقات شرعی + شهرها + قبله
│   └── events/                ← مناسبت‌ها و تعطیلات
├── data/
│   ├── db/                    ← Room (رویدادها)
│   ├── prefs/                 ← DataStore (تنظیمات)
│   ├── model/                 ← منطق تکرار رویداد
│   └── backup/                ← پشتیبان JSON
├── notifications/             ← AlarmManager، یادآوری‌ها، Boot
├── widget/                    ← ویجت صفحه اصلی
├── ads/                       ← AdMob
├── di/                        ← کانتینر وابستگی‌ها
└── ui/                        ← همه صفحه‌ها و تم
```

## نکات فنی مهم

- **دقت تقویم جلالی:** از الگوریتم مرجع jalaali-js (Borkowski) استفاده شده که خروجی آن برای سال‌های ۱۱۷۸ تا ۱۴۳۴ با تقویم رسمی منطبق است. کد با تاریخ‌های شناخته‌شده (نوروز ۱۴۰۳/۱۴۰۴/۱۴۰۵، عاشورا و...) تست شده است.
- **تقویم قمری:** الگوریتم جدولی (کویت) با دقت حدود یک روز. تاریخ‌های رسمی تعطیلات مذهبی در `assets/holidays.json` قرار دارد و مقدم بر محاسبه است.
- **ساعت ایران:** اوقات شرعی با اختلاف ثابت UTC+3:30 محاسبه می‌شود (ایران از ۱۴۰۱ ساعت تابستانی ندارد).
- **یادآوری‌ها:** با `AlarmManager.setExactAndAllowWhileIdle`؛ مجوزهای `USE_EXACT_ALARM` (مجاز برای اپ‌های تقویم طبق سیاست گوگل‌پلی) و `SCHEDULE_EXACT_ALARM` (API 31-32) در مانیفست هست.
- **AdMob:** فعلاً شناسه‌های تست گوگل تنظیم شده؛ قبل از انتشار حتماً `docs/ADMOB-SETUP-FA.md` را بخوانید.

## قدم بعدی قبل از انتشار

1. ⚠️ جایگزینی شناسه‌های AdMob → `docs/ADMOB-SETUP-FA.md`
2. بررسی/به‌روزرسانی تعطیلات سال جدید → `docs/UPDATE-HOLIDAYS-FA.md`
3. امضای نسخه Release → بخش «امضا» در همین فایل
4. چک‌لیست انتشار در گوگل‌پلی و کافه‌بازار → `docs/PUBLISHING-FA.md`
5. انتشار صفحه حریم خصوصی → `docs/PRIVACY-POLICY-FA.md` و `docs/PRIVACY-POLICY-EN.md`

## امضای نسخه Release

1. در Android Studio: **Build → Generate Signed Bundle / APK → Android App Bundle**
2. **Create new…** یک keystore بسازید (فایل `.jks` را هرگز از دست ندهید و رمز آن را جایی امن نگه دارید — برای هر به‌روزرسانی بعدی به همان فایل نیاز دارید)
3. خروجی `app-release.aab` برای گوگل‌پلی و `app-release.apk` برای کافه‌بازار استفاده می‌شود.

یا با خط فرمان: مسیر keystore را در `app/build.gradle.kts` داخل `signingConfigs` اضافه کنید.

## سوالات پرتکرار

**آیا می‌توانم نام اپ یا پکیج را عوض کنم؟**
نام نمایشی: در `res/values/strings.xml` (`app_name`). شناسه پکیج: فقط قبل از اولین انتشار در `app/build.gradle.kts` (`applicationId`) — بعد از انتشار قابل تغییر نیست.

**چرا اینترستیشال نشان داده نمی‌شود؟**
شناسه تست گوگل گاهی کند بارگذاری می‌شود. جزئیات روز را چند بار باز کنید (هر ۳ بار یک‌بار نمایش داده می‌شود — ثابت در `AdManager` و منطق `MainScreen`).
